# Changelog

## master
### ✨ Features and improvements
- **Live uploads become imports of the member's (live API version 2).** `api/live.php?LiveVersion=1` answers `{"LiveVersion":2}`, so Vistumbler's Auto WiFiDB Upload starts a session with the member's username and API key and a title and notes, and gets back its `SessionID`. Every access point sent with that session is the member's, whatever username comes with it. When Vistumbler stops (`completed=1`), what the session sent is written out as a VS1 and put on the import queue with the session's title and notes, so it's imported as that member's like an upload would be; a finished session takes no more. A wrong API key starts nothing; no username at all starts an anonymous one (`AnonCoward`). A session ID WiFiDB didn't hand out is version 1's and works as before. Migration `0014_live_sessions`.
- **Site Settings: the map's elevation tiles can be a TileJSON, with their encoding and highest zoom.** Map elevation tiles takes a TileJSON's address as well as a `{z}/{x}/{y}` one (a pmtiles-swarm `tiles.json`, `#torrent=` and all), and the map reads where the tiles are, their encoding and their maxzoom from it. Two new settings, Map elevation tiles: encoding (as the TileJSON says, Terrarium, or Terrain-RGB) and highest zoom, override it; before, the contours always read Terrarium tiles to zoom 11. PNG and WebP tiles both work. The contour lines read the tiles over HTTPS, not from the swarm.
- **The old WebSocket scheduling page is gone.** `opt/scheduling.php?func=websockets` never drew its tables (the functions its `WebSockClient.js` called were never written) and reloaded itself, ad and all, every 15 seconds; nothing linked to it. The scheduling pages in the menu have updated themselves in place since February (`scheduling.live.js` and `opt/scheduling_api.php`), and that's how they stay.
- **The websocket daemon is gone.** `websocketd.php` served only that page and a Live APs feed no page asked for (its queries were MariaDB-only besides), so it, `wifidb-websocketd`, the `/ws/` proxy, `WebSocketURL` and the daemon config's `WebSocketBindIP`/`WebSocketPort` are taken out, along with the `sockets` extension it needed. A Proxmox container's update stops it and removes its unit; the proxy in front no longer needs a long tunnel timeout for `/ws/`. `WIFIDB_WEBSOCKETD` in `firstboot.env` does nothing now.
- **Preferences ask first, and can remember the computer.** For a member who chose to be asked, opening their preferences shows "Confirm it is you" on its own page (no control panel tabs above a page they can't use yet) and then takes them there. It has **Remember this computer for 30 days**, the same as signing in: one tick skips both questions on that computer. Each preferences page opened keeps them open another 10 minutes, so they don't close while in use. Admin mode still asks every time.

## 1.0.0-rc.2
### ✨ Features and improvements
- **Search: choose how each field matches.** Each field on the search page has Equals (the default), Contains, Starts with or Ends with, and so do `api/search.php` (`ssid_op`, `mac_op`, `radio_op`, `chan_op`, `auth_op`, `encry_op`), the results' paging and sorting, and their Map, JSON, KMZ and GPX links. A blank field is no longer searched on at all, and a field is no longer always wrapped in `%…%`, which made every search read the whole table: what made wifidb.net's search time out. A value with a `%` in it is still a `LIKE` pattern as typed. Searching with every field blank sends you to the full list, as `%` did. (wifidb.net ran this from September 2026 without it reaching the repository; there, the Map and exports from a search had stopped working.)
- **Site Settings: Map elevation tiles.** Where the mobile theme's map gets the elevation it draws contour lines from (Terrarium PNG tiles, an address with `{z}`, `{x}` and `{y}`); `https://tiles.wifidb.net/data/jaxa_terrarium/{z}/{x}/{y}.png`, as before, unless set. Empty: no contour lines.
- **The upload page picks the Import Type for you.** Choosing files reads the start of each and selects the type they look like (a WiGLE or SWardriving CSV by its first line, a Wardrive database, a NetStumbler NS1, a VSZ or MDB, a Kismet netxml by what's in them, then by the name), and says so; the choice is still yours. Files that look like different types are pointed out rather than guessed. An upload sent without a type gets the same check for each file instead of being taken for Vistumbler's.
- **`load_geonames.php` downloads the GeoNames files itself.** `php load_geonames.php --all --download --replace` fetches the country names, regions and places from download.geonames.org (into `/srv/wifidb-data/geonames` on a Proxmox container, or `--dir`) and loads them; a file already downloaded is used again. `--set=cities500` (or `cities1000`, `cities5000`, `cities15000`) loads one of GeoNames' lists of towns instead of all 12 million places. A zip, downloaded or given with `--file`, is read without unpacking it.
- **The GeoNames places can refresh themselves.** Site Settings has *Refresh the GeoNames places* (off, every month or every 3 months) and *Which GeoNames places* (every place, or towns of 500, 1,000, 5,000 or 15,000 people or more). `tools/cron/geonames` checks each night (04:50 in the Proxmox template) and, when a refresh is due, downloads GeoNames' files again and loads them as `load_geonames.php --scheduled`: the places stay in use throughout. One node does it; the others find it done.
- **`load_geonames.php` updates the GeoNames tables in place.** Loading again updates each place, region and country that's there and adds the new ones, so the site keeps its nearby places while a new GeoNames download goes in (before, a second load without `--replace` added every place and country a second time on SQL Server and PostgreSQL). Each row is stamped with when it was loaded (`loaded_at`), and once the whole file is in, the rows it didn't stamp, what GeoNames has since removed, are taken out: a table ends up as the file has it (`--keep` leaves those rows; a load with lines that couldn't be saved leaves them too). `--replace` still empties the tables first. Rows go in several hundred to a statement (a MERGE on SQL Server) rather than one at a time, so a load of every place takes a fraction of the time; a batch that fails is tried a row at a time, so one bad line is all that's left out. Migrations `0011_geonames_keys` (the places keyed by `geonameid` and the countries by ISO code, after taking out the copies an earlier load may have left) and `0012_geonames_loaded`: run `tools/utilites/migrate.php` after updating (a Proxmox container's update does).

### 🐞 Bug fixes
- **Places nearby are the nearest ones, wherever they are.** An access point's places nearby, and `api/geonames.php`, only looked in the 0.1 degree square the point was in (by the text of the latitude and longitude), so a place just over the line was never found, and a point in an empty square found nothing at all. They now look in a box around the point, wider where nothing is close, by the position as numbers: migration `0013_geonames_coords` adds `lat` and `lon` to `geonames` and indexes them, and fills them for the places already loaded (on a big table this takes a while; `load_geonames.php` fills them from then on). Every kind of place is still listed, landmarks too.
- **`api/geonames.php` finds the place nearest the point asked about.** It measured every place's distance from a point it never set, so the "nearest" was whichever place in the square came first; and a `lat` or `long` that isn't a number gave an error instead of saying so.
- **WiGLE and SWardriving CSVs sent through `api/v2/import.php` import.** The API took every `.csv` for a Vistumbler one, and a `.wiglecsv` for a type the importer doesn't know; it now looks at what's in the file, as the upload page does.
- **Update every server works on SQL Server.** Asking for an update from Admin > Servers failed with "That didn't work": the request named its `backup` column, a reserved word in SQL Server, without brackets.
- **Big tile archives join the swarm in the browser again.** The map waited a fixed 30 seconds for an archive's torrent while the engine allows more for one with many pieces, so a large archive always fell back to plain HTTP. The engine's own budget is now the only one. pmtiles-torrent is 0.11.1, as wifidb.net already ran: it also asks for an archive's last piece first, where planetiler puts the directories, and gives a large archive's metadata longer.

## 1.0.0-rc.1
### ✨ Features and improvements
- **Updates bring pmtiles-swarm's release too.** The template records the pmtiles-swarm release it was built with (npm's `package.json` and `package-lock.json`, in `/opt/wifidb/swarm`), and each update package carries it. On a server with another release, the first boot installs it with `npm ci` beside the installed one and switches over once it's in, its WebRTC binary loads and it answers on port 8090; otherwise the one before stays or goes back, with a warning. A rolled-back update puts back the release that goes with the old code. To try another release on one server, change `/opt/wifidb/swarm` and run the first boot. See `docs/pmtiles-swarm.md`.
- **Admin > Servers shows pmtiles-swarm** on the servers that run it: whether it's running and answering, its release, whether it publishes the archives or mirrors them, and how many categories it has. It calls out a swarm that's stopped or not answering, and a mirroring server that still hasn't got the newest build of a category half an hour after the publishing server made it. Each server reads its swarm's public `/health` and `/categories.xml` on port 8090, so the site needs no key of the swarm's.
- **An Admin section in the menu** for administrators, after WiFiDB Links: **Turn on admin mode**, and while it's on, the admin pages (Files Bad, Site Settings, Sign-in Providers, Mail, Backups, Servers, Traffic) and **Leave admin mode**. The admin pages were mixed in with WiFiDB Links and showed even outside admin mode, where each only sent you to turn it on.
- **Turn a scheduled job off or on from the scheduling page.** In admin mode, each row of the Daemon Schedule has **Disable** (⏸) or **Enable** (✔) beside Reset and Run Now, after a confirmation (a form that posts, unlike the older actions' links). Off, the daemons on that node no longer take the job; a run already going finishes. A disabled row now says *(disabled)* after its status, so a red row that's only switched off no longer looks like a failure. This is how the KML export and stats jobs move to another node.
- **pmtiles-swarm in the Proxmox template: every node a swarm node.** The template installs [pmtiles-swarm](https://github.com/TechIdiots-LLC/pmtiles-swarm) from its npm release (0.107.2; `WIFIDB_SWARM_PACKAGE` builds with another), off until `WIFIDB_SWARM=1` in `firstboot.env`. The node that builds the tile archives then watches its archive folders and publishes each build under its `wifidb-<bucket>` category (and `wifidb-mlt-<bucket>` for MLT archives), with the piece size and kept builds wifidb.net's swarm uses, signed into the DHT with a key of its own; every other node (`WIFIDB_SWARM_FOLLOW`, the building node's address) mirrors them into its own archive folder under the same names, so each node's site and swarm serve the same archives on port 8090, behind HAProxy's `data.<site>` name. Its settings, catalog and key are on the data disk; it runs as its own account, which shares only the archive folder with the site; its console stays inside the container. With it on, `out_sync` leaves the archives to it (`out_sync_skip`), and only the building node records the current builds for the map page. See `docs/pmtiles-swarm.md`.
- **An Admin section in the User Control Panel** for administrators, under the control panel's own links: **Turn on admin mode** (which comes back to the control panel), or, while it's on, **Leave admin mode**.
- **Gmail and Google Workspace mail can sign in with a Google account (OAuth) instead of a password.** Google no longer takes the account's own password from mail programs, and steers away from app passwords. On the Mail page, save the site's own OAuth client and **Connect with Google**: only a refresh token is kept, encrypted, so every node signs in with it. The sign-up account can have its own. The check asks Google for an access token, and when Google has taken the token back (a changed password, six months unused, access removed) the log and the check say to connect again. App passwords still work. See `docs/email.md`.
- **Mail is set up on the site** (**Mail** in the menu, `admin/mail.php`, needs admin mode) instead of in `config.inc.php`, which still gives the starting values: the mail server and account (with a From name now), whether notification mail is sent, a separate sign-up account if wanted (anything it leaves empty is the main account's), and DKIM signing. **Make a key** makes the DKIM key and keeps it in the database, encrypted as the password is, so every node signs with it, and shows the DNS record to publish. **Check** checks the settings and the domain's DKIM, SPF and DMARC records, and **Send a test message** shows what the mail server said, without the login. `check_mail.php` checks what the page saved too. See `docs/email.md`.
- **Traffic, counted by the site itself** (**Traffic** in the menu, `admin/traffic.php`, needs admin mode), as tippr's traffic pages, in place of AWStats: page views and unique visitors by hour, day and month, by day of the week, by country and by page, and what people did (sign-ups, sign-ins, failed sign-ins, uploads from the site and the API, imports finished and set aside). Each node writes to a file of its own and `tools/cron/traffic` adds it to the database each minute, so with several nodes it's the whole site in one place. Visitors are told apart by a salted hash, deleted once its period is over: no address is kept. New tables `traffic_counts` and `traffic_visitors`: run `tools/utilites/migrate.php`. See `docs/traffic.md`.
- **robots.txt, the sitemaps and ads.txt are made from the site's own address and Site Settings,** instead of files written for wifidb.net. The sitemap now lists every member with a finished import and every finished import (in pieces of 50,000) as well as the main pages; ads.txt is the AdSense line for the publisher ID unless Site Settings has its own text (the old `Ads.txt` was named so that Linux servers never served it at `/ads.txt`). Every page's canonical link and `og:url` use the site's address rather than wifidb.net's, and Site Settings has the site's description (it replaces the `header` option in `config.inc.php`), Google and Bing verification codes, and **Keep search engines out**, for a test or staging copy. See `docs/site-settings.md`.
- **Google Analytics and AdSense are set on Site Settings, and the cookie banner shows only where consent is required.** The measurement ID, publisher ID and ad unit (paste them, or Google's whole tag) were written into both themes' templates, so another site running WifiDB counted its visitors in wifidb.net's Analytics; now nothing of Google's loads until they're set. *Visitors' consent* asks where it's required (the EU and the rest of the EEA, the UK and Switzerland, by the visitor's country, looked up on the server), every visitor, or nobody; **Cookie choices** in the footer changes a choice. The banner no longer sends each visitor's address to ipapi.co to find their country: a copy of DB-IP's free country database is kept on the server and refreshed monthly by `tools/cron/update_geoip`, and a failed refresh keeps the copy that works (the Proxmox template ships one). The old `ads` and `tracker` settings in `config.inc.php` are gone. See `docs/site-settings.md`.
- **Sign in with Google, GitHub, Discord or Facebook.** Members link an outside account under User Control Panel → Security (with their password) and then sign in with it from the sign-in page; their second factor is still asked for if they have it on. Signing in with one that isn't linked offers to sign in with a password and link it, or to sign up with it. Only a linked account signs in to a member's account: nothing is matched by e-mail address. Nothing is on until an administrator turns a provider on at the new **Sign-in Providers** page (`admin/logins.php`, needs admin mode) with the site's own OAuth client ID and secret. Works with several nodes behind a load balancer. New tables `user_linked_logins` and `linked_login_states`: run `tools/utilites/migrate.php`. See `docs/linked-logins.md`.
- **SQL Server connection security is a setting.** `sqlsrv_encrypt` and `sqlsrv_trust_server_certificate` in `config.inc.php` (both on by default, as before; `WIFIDB_SQLSRV_TRUST_CERT=0` on the Proxmox template). Turn the second off once the SQL Server has a certificate the web server trusts, and the connection is checked as well as encrypted.
- **The Proxmox template answers at the API's own name too** (`api.wifidb.net` on wifidb.net): the `api/` folder at the top of `api.<site>`, as wifidb.net's own server has it, so Vistumbler and other clients using that name keep working. `WIFIDB_API_HOST` sets other names (several, separated by spaces, such as `"api.wifidb.net api.vistumbler.net"`), or none.
- **Shared files in S3, for several nodes on one database.** With *Shared files in S3* set in Site Settings, the bucket is where uploads are kept: each one (from the upload page or Vistumbler's API) is put there before it's queued, any node's importer fetches it and removes that working copy afterwards, and deleting an import moves it to `deleted/` in the bucket, as `import/up/deleted/` without it. If the bucket can't be reached, the upload is refused rather than queued where only one node can see it. See `docs/proxmox.md`.
- **Generated files kept the same on every node through the shared files bucket.** `tools/cron/out_sync` (every two minutes) pushes the tile archives, GeoJSON and KML exports a node builds and pulls those the others built, removing what's gone on either side; every node still serves `out/` from its own disk. Hard and symbolic links (an archive's stable name, the exports' latest links) stay links, so each archive is stored once. Without the bucket nothing changes. See `docs/proxmox.md`.
- **Admin > Servers: every server at a glance, and updates from the page.** Each server reports each minute (version, load, memory, disks, services); the page calls out one that's silent, behind, short of disk or memory, busy or with a service down. Pick a release and every Proxmox container updates itself, one at a time: the root-owned updater (`wifidb-update`, on a timer) downloads the release's new update package, checks it against `SHA256SUMS`, waits for running jobs, installs it and runs the first boot (migrations included), and puts the old version back if the site doesn't answer. Releases come from GitLab by default, or GitHub (`WIFIDB_UPDATE_*` in `firstboot.env`; a token for a private project stays in root's own file). Both release pipelines now publish `WifiDB-v<version>-update.tar.gz` and `SHA256SUMS` beside the template. New tables `server_status` and `server_update_requests`: run `tools/utilites/migrate.php`. See `docs/updates.md`.
- **Each upload is queued with the node it came in on** (`files_tmp.node_name`, `files_importing.node_name`: run `tools/utilites/migrate.php`). Without the shared files bucket only that node's importer takes it, so on several nodes an upload is no longer set aside as missing by a node that hasn't got the file. The upload page and both versions of the API now queue uploads the same way (`lib/import_queue.inc.php`); the v2 API also gets the shared files bucket. Uploads queued before the migration go to any node, as before.
- **More than one node on one database.** Building tiles and GeoJSON, updating the manufacturer list and the nightly backup now run under a lock held in the database (`tools/daemon/lock_run.php`, used by the cron scripts), so only one node does each at a time; on one node nothing changes. An admin job is now taken by one node only, and on SQL Server the importer takes the next file in one transaction, passing over files another importer holds. See `docs/proxmox.md`.
- **PostgreSQL support** (merged from the postgresql branch): `blank_db.pgsql`, a `pgsql` branch for the queries, PostgreSQL migrations, backups that move to and from it, and the Proxmox template (`WIFIDB_DB_TYPE=pgsql`). The database user needs to own its database, not be a superuser. `tools/utilites/pg_audit.py` lists query sites still to check.
- **Usernames are matched exactly in the API export too** (`api/v2/export.php` still used `LIKE`).
- **Backups that move between SQL Server and MariaDB** (`admin/backups.php`, needs admin mode, and `tools/utilites/backup.php`). One file holds the whole database; one made on SQL Server restores on MariaDB and the other way round, which also moves a site to a new server. Back up now or nightly (newest 7 kept), download (resumable), restore (type the domain to confirm; scheduled daemons wait meanwhile; the backup's key for authenticator apps comes with it). See `docs/backups.md`.
- **Copy a backup from another server** with a transfer key made on that server's Backups page (7 days, shown once): 16 MB pieces, resumes after an interruption, SHA-256 checked, optionally a fresh backup first and a restore after.
- **Backup copies in S3** (Garage, MinIO, AWS): set the bucket on Site Settings and each nightly backup is copied there (newest 30 kept); the Backups page lists the bucket and fetches from it.

Sign-ups open or closed, e-mail confirmation for new accounts, and CleanTalk are changed there instead of in `config.inc.php`, which still gives their starting values. Changes leave the administrators a notice. New table `site_settings`: run `tools/utilites/migrate.php`. See `docs/site-settings.md`.

- **Optional spam check with CleanTalk** for sign-ups and for private messages from newer members. It is off until an administrator adds a key; a key CleanTalk refuses is not saved. If CleanTalk can't be reached, sign-ups and messages go through. The privacy policy now says what is sent to CleanTalk.

It asks for a fresh authenticator or recovery code, or a passkey, each time it is turned on (the code that signed you in does not count), and ends after 30 minutes without an admin page or with *Leave admin mode*. Administrators without two-factor are sent to add it. New command `tools/utilites/reset_two_factor.php USERNAME` recovers a member who is locked out. See `docs/two-factor.md`.

Upgrading it is a one-line change plus a test run (the tests compile every template). The Proxmox template runs `composer install --no-dev` when it is built.

### 🐞 Bug fixes
- **The scheduling page's Daemon Status shows the daemons again on current Linux.** The monitor daemon asked `ps` for each daemon in a format the `ps` in the Proxmox template (procps-ng 4.0.4, Ubuntu 26.04) refuses, so every daemon showed in red as pid 0 with "There was no data in the PS return", running or not. It now asks for the fields by name.
- **The map shows the attribution once.** Each tile archive's attribution had its build date in it (`© WifiDB 2026-11-02`), so every archive's was different, and the map listed one for every source; `api/tilejson.php` had a third wording. Every source now carries the same one, `© WifiDB contributors`, linked to the site's own address (`mvt_attribution()`). Archives built before this keep theirs until their next build.
- **Each tile archive build has a name of its own** (`<bucket>-YYYYMMDDhhmmss.pmtiles`, UTC; it was the date alone). `daily` and `cell_daily` are rebuilt every hour, so every build after a day's first was renamed over the file pmtiles-swarm had already made a torrent of: the swarm went on seeding bytes that were gone, and never published the new ones. Older builds named by the date alone are retired as before. The archive folder also refuses `*.incomplete` files, which a node mirroring the archives downloads into.
- **A passkey turns on admin mode.** Admin mode needs the passkey to check who you are (a PIN or fingerprint), but the page asked the browser not to, so the browser at most asked for a touch and the passkey was refused. The server now tells the browser to ask. The page says why a passkey was refused (too many tries, too slow, not on the account), and the log says what was wrong with it, for admin mode and for signing in.
- **The new pages' explanations wrap** (Admin mode, Security, Site Settings, Mail, Backups, Servers, Traffic and the rest). They were in the theme's column-heading style, which never wraps, so a long one ran past the right edge of the page and pulled the table with it. On Security, adding an authenticator app or a passkey is now in the table rather than below it.
- **A sign-up, resent confirmation or password reset whose mail couldn't be sent says so.** It told the member the mail was on its way whenever the mail server refused it or couldn't be reached, because PHPMailer says so by returning false rather than by an error. The reason now goes in the log.
- **A mail server that doesn't answer no longer breaks the sign-up page.** PHPMailer waited up to 5 minutes for it, and the web server gave up after 30 seconds with an error page (the account was made, but the page never said so). It now gives up after 15 seconds (`smtp_timeout`) and the page says the confirmation mail couldn't be sent.
- **Signing in to an account that hasn't confirmed its e-mail says so** (it said "Unknown Return."), and a username that doesn't exist no longer gives PHP warnings; it's still answered as a wrong password.
- **The site says when the database needs updating.** If the database hasn't had every migration in `sql/migrations/`, pages answer 503 naming the missing ones and saying to run `tools/utilites/migrate.php`, and the daemons don't start, instead of failing on a missing table. This replaces the old check of `settings.version`, which opened a second database connection on every request and pointed at install pages that no longer exist. `migrate.php` and `backup.php` still run.
- **The footer's version is the released one.** It showed a fixed "v0.40 Beta"; it now shows `VERSION` (`v0.40.0`), from `lib/version.inc.php`, which the version bump updates with `VERSION`.
- **Admin jobs (deleting and resetting imports) and the Stats page's figures were never worked out on a new install:** admind and statsd only run for a node with an `Admin` or `Stats` row in `schedule`, and the schema had neither. Migration 0006 gives each node without one an `Admin` row; migration 0007, if no node has a `Stats` row, gives each node one, switched on for the first node only and run hourly. Run `tools/utilites/migrate.php`; rows you already have are left alone. statsd also waited for nothing: started by cron each minute, it worked the stats out each minute; it now waits for its next run.
- **Vistumbler's .mdb files import again:** the importer reads them with mdbtools' `mdb-export`, which the Proxmox template didn't have, so every one came out with nothing in it; it's installed now, and a server without it sets the file aside saying so. The file name also went into that command unquoted; it's quoted now.
- **Removed what had been replaced:** `cron/update_geonames` (it ran `geonamed.php`, removed in 2018 when the access point page started finding nearby places itself), the v2 API's `exp_all_countries`, `exp_country`, `exp_admin1` and `exp_admin2` (they read the country and region columns that daemon filled, which `wifi_ap` no longer has), `update_pointers_manuf.php` (the manufacturer daemon does it), `update_userlist_gpsbox.php`, `PrePopulateDailyFolders.php` (`GenerateDaemonKMLData` does it) and the unfinished `DoesAPWander.php` test.
- **Uploads from Vistumbler (the API) failed on MariaDB and PostgreSQL,** and were reported as failed even when they were queued; `.netxml` uploads through it were refused as unsupported.
- **Imports on MariaDB failed at the first file.** Adding an access point had no MariaDB version (only SQL Server's and PostgreSQL's), so every import stopped on a foreign key error; and taking the next file off the queue used column names MariaDB no longer has.
- **A file the importer can't read no longer stops the import run.** A file that isn't what its type says, or one that trips a bug, used to end the run and stay "importing" for good. Now it goes to the bad files with the error as its reason, what it got as far as writing is taken out again, and the next file is imported.
- **`.gz` and `.VSZ` uploads always failed:** the `import/up/extract` folder they're unpacked into was never made. The importer makes it now. A `.VSZ` without a line-break byte in it was also taken for an empty file.
- **The maintenance utilities work on all three databases** and on today's tables: `update_files_validgps.php`, `NewAPPercentCalc.php`, `update_high_gps.php` (works out an access point's first and last seen, best signal, points and best GPS point again from its readings), `fix_dates.php`, `geojson.php`, `file_cleanup_signal_data.php` and `load_geonames.php` (the files from https://download.geonames.org/export/dump/, a line at a time). The Proxmox boot tests run them.
- **Sign-up and password-reset mail was never DKIM-signed.** Only the main mailer had the DKIM settings; the sign-up mailer now has them too.
- **Sign-up and password-reset mail failed on a config built from the example file.** The mailer reads separate `signup_smtp_*` settings, but `config.inc.php.example` did not have them. They are now optional and fall back to the main `smtp_*` account, with a documented commented-out block in the example for using a separate account.
- **`rund.php ver` and `rund.php help` printed blanks and warnings.** They read version numbers from a variable that was never in scope; they use the core's version now.
- **Security: the signal graph page (api/wifi, opened from Vistumbler) wrote the access point's name and other values into the page unescaped,** so a crafted link ran script in the visitor's browser. Everything is escaped now, the colors and the signal list are validated before they reach GD (a bad color is an error on PHP 8), and the text and number of points are limited. Vistumbler's links work unchanged.
- **Security: a crafted login link could run script in the visitor's browser and send them to another site.** The `return` address on the login page went into an inline script unfiltered. Return addresses are now accepted only if they are paths on this site (or this site's own address), on the login page and on the confirm pages for deleting imports and the admin actions, and the page writes the address into its script as a safely encoded string.
- **Security: a crafted theme cookie could point the template and compile folders anywhere.** The theme name is now
  accepted only if it is a folder in `themes/`.
- **Security: passwords are stored with bcrypt at cost 12** (was cost 7), checked in constant time. Existing passwords
  keep working and are upgraded the next time their user logs in. Back up `user_info` before upgrading.
- **Security: the login and theme cookies are `HttpOnly` and `SameSite=Lax`.**
- **Security: SSIDs, usernames, titles, notes, labels, MACs and values taken from the address are escaped in both
  themes' templates**, without double-escaping what PHP already escaped.
- **Security: session IDs, API keys and salts come from `random_int()`** instead of `mt_rand()`.
- **Security: removed `tar_file`,** which built a shell command from its argument and was never called.
- **`blank_db.sql` could not be imported into an empty database:** `cell_id` had its primary key defined twice.
- **PHP 8 fatals and deprecations:** string offsets with `{}`, the removed `__autoload()`, `implode()` argument order,
  optional parameters before required ones, the backtick operator, `case x;`, and the old cast names. Properties
  that classes made by assigning them (deprecated in PHP 8.2, an error in PHP 9) are declared in their classes.
- **`FILTER_SANITIZE_STRING`** (deprecated in PHP 8.1) is replaced by `wifidb_input_string()`, with the same result.
- **Removed what could not run:** 26 utilities (dropped tables, deleted libraries, stubs), the pthreads prototype
  (pthreads does not exist in PHP 8), dead `mysql_*` code, and two templates that did not compile. Four utilities
  that used the dropped `wifi_signals` table now use `wifi_hist`.
